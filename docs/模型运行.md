# 同一模型运行 FastSim 与 Gazebo

使用 models/road_v2/candidate_167.npz。模型来源与校验值见 models/road_v2/模型说明.md。

## 快速仿真与 A–D

从仓库根目录运行：

```sh
python -m evaluation.road_eval --model models/road_v2/candidate_167.npz --level L6 --count 2 --workers 1
python -m evaluation.road_track --model models/road_v2/candidate_167.npz --tracks A B C D --caps 0.7 --count 1 --workers 1 --fill-v
```

## Gazebo

先按 simulation/gazebo/说明.md 构建。三个终端都先 `export ROS_DOMAIN_ID=60`(或同一个空闲域)。在三个终端中分别运行，均从仓库根目录开始。

终端一：启动旧版 trackA 场景（不是 maps 中当前 A–D 的同一评测集）。

```sh
bash simulation/gazebo/run_sim.sh use_gui:=false world:=trackA.world spawn_x:=11.0 spawn_y:=0.75 spawn_yaw:=0
```

终端二：加载模型，等待使能。ROS 依赖使用 Ubuntu 系统 Python。

```sh
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=60
python3 -m vehicle.road_policy_node models/road_v2/candidate_167.npz --speed-cap 0.7
```

终端三：限时使能并检查移动、取消使能后的零速输出。

```sh
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=60
python3 -m simulation.gazebo.probe_model --seconds 10 --out runs/gazebo_probe.json
```

域必须与 run_sim.sh 相同(默认 60,可用环境变量改;共享服务器上 43–50、84 已被占用),节点拒绝未设置或实车域 42。使用 /clock，订阅 /scan、/IMU_data 和 /ackermann_steering_controller/odometry；输出 /cmd_vel 的 m/s、rad/s。传感器过期、心跳过期和退出时输出零速。

两条链路都从归一化动作映射到舵机刻度，再调用同一实测转向曲线；Gazebo 随后按轴距换算偏航角速度。不发送实车 PWM。Gazebo 的轮胎/控制器动力学与 FastSim 近似模型仍不同，执行链通过不等于跨仿真圈速和通过率一致。
