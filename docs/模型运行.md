# 同一 road_v2 模型运行 FastSim 与 Gazebo

默认模型为 `models/road_v2/candidate_167.npz`，输入 53 维 × 5 帧，输出转向和目标速度。模型来源、MD5 与既有评测记录见 `models/road_v2/模型说明.md`。

## FastSim：随机路段与官方 A–D

在仓库根目录运行。先用少量局确认模型文件、观测维度和仿真入口正常：

```sh
python -m evaluation.road_eval --model models/road_v2/candidate_167.npz --level L6 --count 2 --workers 1
```

官方赛道测试集来自 `maps/`。下面命令测 A–D、限速 0.7 m/s、每条赛道一个随机车辆种子；`--fill-v` 表示黄 V 区也铺锥桶，不测试胶带版本：

```sh
python -m evaluation.road_track --model models/road_v2/candidate_167.npz --tracks A B C D --caps 0.7 --count 1 --workers 1 --fill-v
```

正式比较时增加 `--count`（建议每档至少 30 局），并通过 `--out` 保存明细。FastSim 每次从同一套 `common.params.CarParams` 和实测转向曲线推导转角。

## Gazebo Classic：运行官方赛道

ROS 2 Humble/Gazebo 的构建步骤和隔离要求见 `simulation/gazebo/说明.md`。先从同一份官方赛道生成 world 和评分布局，再运行模型；下面以 A 为例：

```sh
python3 simulation/gazebo/official_to_gazebo.py --out runs/gz_official --tracks A B C D
POLICY_SPEED=0.7 bash simulation/gazebo/run_road_policy_once.sh \
  runs/gz_official/track_A/track_sim.world \
  models/road_v2/candidate_167.npz \
  runs/gz_official/track_A/layout.yaml \
  runs/gz_official/track_A/result.json
```

对 B、C、D 将 `track_A` 改为相应目录。单次脚本负责启动 Gazebo、road_v2 推理节点、心跳与评分，并写出 JSON 结果和诊断日志；共享服务器并行运行时按 `simulation/gazebo/说明.md` 选独立 worker 槽位。

仿真侧由同一 `common.road_runtime` 把网络转向动作经 `common.pwm.action_to_steer` 和 `CarParams.steer_curve` 换算为前轮角，再用轴距 0.33 m 换成 `/cmd_vel` 的偏航角速度；没有实车 PWM 换算。Gazebo 控制器/轮胎动力学与 FastSim 的简化车辆模型不同，所以单次执行成功只证明链路可运行，跨仿真的通过率和圈速仍须分别测量。
