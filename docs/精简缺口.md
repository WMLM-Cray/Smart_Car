# 精简分支缺什么、去哪找

`docs/整理说明.md` 写了「移除旧训练器、历史导航方案、重复报告和中间模型」，但没有说**具体缺哪些**、**要找去哪找**。这份清单补这两件事。

基线是 `0ed23c4`（精简前的最后一个完整快照，也就是 `735c12b` 的父提交），对照 `dreamfish`。共 **569** 个路径在精简中被丢弃，其中绝大多数（`docs/` 215 篇、`3Dsim/` 71 个）是过程材料。下面只列**有代码价值、且现在真的没有替代品**的部分。

## 要找旧东西，去这三个地方

| 位置 | 是什么 | 怎么取 |
|---|---|---|
| `rc` 分支（`014cbbf`） | 精简前的完整旧布局 | `git checkout rc` |
| tag `main-before-restructure-2026-09-26` | 同上，同一个提交 | `git checkout main-before-restructure-2026-09-26` |
| 提交 `0ed23c4` | 迁移表的**源**基线 | `git checkout 0ed23c4` |

> ⚠️ 别用 `main` 找旧代码。`main` 现在就是精简版（`e53f65a`），和 `dreamfish` 同源。旧布局在 `rc`。

迁移表 `docs/文件迁移.json` 描述的是 **`0ed23c4` → `735c12b`** 这一次重组（117/118 条源路径命中 `0ed23c4`），不是 `main` 的某次改动。它只收录了 118 条 —— 是**挑选过的**，不是全量清单。表里没有的路径不代表被有意丢弃。

## 一、v1 训练线（`fastsim/` 15 个文件）

**这是最大的一块，而且它不是「遗漏」——`docs/整理说明.md` 明说了「移除旧训练器」。**

| `fastsim/env.py` | 180 | `ConeTrackEnv`，含 `sectorize()`（48 扇区压缩） |
| `fastsim/cone_follow.py` | 168 | 锥桶跟随基线 |
| `fastsim/train.py` | 140 | 训练入口 |
| `fastsim/low_speed_eval.py` | 100 | v1 评估 |

| `fastsim/interop.py` | 80 | 与 Gazebo 的互通层（见下） |
| `fastsim/mapping.py` | 75 | `FREE`/`OCCUPIED` 栅格 |
| `fastsim/pwm.py` | 63 | 旧线性 PWM 速度换算 |
| `fastsim/sensors.py` | 52 | `Lidar` |
| `fastsim/tests/test_sim.py` | 426 | 上面这些的测试 |
| `fastsim/tests/test_low_speed.py` | 88 | v1 训练/评估测试 |

**后果：`models/steering_v1/` 里的模型在 dreamfish 上无法重训。** 模型留下来了（`models/steering_v1/candidate_060.npz`），训练它的代码没留下来。`vehicle/steer_policy_node.py` 还在，能**跑** v1 模型；但改不了、重训不了。

这不是该在移植 PR 里顺手决定的事，是架构决策：要么明确接受「v1 冻结、只跑不训」，要么把训练线请回来。

### 两个特例

**`fastsim/pwm.py` 的删除是刻意的，别当成遗漏。** `common/pwm.py` 的 docstring 写明了理由：速度目标改由 `vehicle/speed_loop.py` 的 PI 闭环控制，不再用旧的线性 PWM 速度换算；转向改用实测 `steer_curve` 插值。

后果是 `pwm_to_speed()` / `speed_to_pwm()` 在整个仓库里**没有对应物**。这两个函数是旧仿真把 PWM 刻度当车速用的桥；新链路里仿真直接吃 m/s，不需要桥。**只有一处例外**：v1 模型若要在仿真里跑（`teleop/policy_node.py --sim` 那条路），就得有它。

**`fastsim/interop.py` 是半覆盖的。** `common/control.py` 只搬了 `to_cmd_vel`（4 行）：
```python
def to_cmd_vel(v, steer, p=CarParams()):
    return float(v), float(v * math.tan(steer) / p.wheelbase)
```
丢掉的是：
- `from_cmd_vel()` —— 反函数，**全库无对应物**
- `export_track()` —— 把 fastsim 赛道写成 `track_generator` 认的 `cones.csv` + `gaps.json`，**全库无对应物**。它是「随机生成的赛道拿到 Gazebo 里复现同一条」的唯一通道。
- `_align_to_start()` —— 起点归零

## 二、`teleop/` 未收录的 10 个

### 现在真的没有替代品的

| 文件 | 行数 | 为什么值得注意 |
|---|---|---|
| `teleop/floor_probe.py` | 230 | 测 **维持点 / 破静点**。见下 |
| `teleop/pwm_sweep.py` | 171 | 升序 PWM 扫描；**`--duty-at` 占空比模式无替代** |
| `teleop/mapping_probe.py` | 36 | 建图输入只读探针：`/scan`、`/encoder`、`/odom_combined` 计数 + TF 链 |
| `teleop/test_policy_cmd.py` | 107 | 钉 `to_cmd` 的口径：PWM 限幅、仿真发的是偏航角速度而非转角 |

**`floor_probe.py` 这一条最值得单独说。** 它测的两个数现在**硬编码在** `vehicle/speed_loop.py` 里：

```python
pwm_floor: int = 1590       # 车在动时的最低输出 —— 低于它会停,随电量变
pwm_breakaway: int = 1594   # 从静止起步的最低输出 —— 必须 >= pwm_floor
```

`pwm_floor` **随电量变**，而注释也写明了它只往上学、不往下探。测它的工具没进 dreamfish，等于这两个数以后只能靠猜或者手动改代码。`calibration/ramp_curve.py` 能覆盖一部分（它也在测维持点/破静点），但 `floor_probe.py` 的**一次一个候选值**做法是室内短直线唯一可行的方式 —— 它的 docstring 解释了原因：降序连续扫要一口气跑十几米，室内没这么长的直线。

`test_policy_cmd.py` 覆盖的口径，dreamfish 的 `vehicle/test_steer_policy.py` 里**没有**：那个文件测的是 `observe()` 的六个参数顺序、`last_steer` 存原始输出、爬升速率，没有一项测 `to_cmd` 的 PWM 限幅或偏航角速度换算。

| `teleop/hold_enable.py` | 仿真里的 `/policy_enable` 心跳源，PR #8 会带进来（**尚未合并**） |
| `teleop/sim_reset.py` | 已在 `simulation/gazebo/sim_reset.py`（PR #10，已合并） |

## 一句话总结

- **v1 训练线**：模型留了、训练代码没留，`models/steering_v1/` 在 dreamfish 上只跑不训 —— 需要团队决定接不接受。
- **`floor_probe.py`**：它测的两个数现在硬编码在 `vehicle/speed_loop.py`，而其中一个随电量变。
- **`export_track` + `track_generator`**：一对导出/消费，两端都不在，通路整条断。
- **systemd `.d/` 覆盖**：4 个 service 本体搬了，覆盖目录一个没搬。
- 要找旧代码去 **`rc` 分支**，不是 `main`。
