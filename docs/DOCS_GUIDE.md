# Markdown 编写与压缩规则

目标：读者能快速找到当前做法、适用条件、验收要求和证据。

## 当前说明保留

- 做什么、入口文件和可直接执行的命令。
- 输入/输出、依赖及接口单位。
- 本次包含和不包含的工作。
- 验收条件、未验证项和适用边界。
- 代码版本、测量条件和原始数据链接。

建议长度：项目入口约 80 行内，模块说明约 80 行内，任务计划约 60 行内，交接约 100 行内。按内容需要调整，不为凑行数删事实。

## 历史与证据

逐次实验记录属于证据：保留当时参数、日期、失败现象、数据路径和结论范围。新结论写在当前入口，并链接历史记录；不要悄悄改旧结果或把历史 PASS 当作当前版本 PASS。长报告若不再作为入口，可在开头标“历史记录”并链接当前做法。

## 压缩时删并

重复背景、重复参数表、聊天时间线、已被代码取代的操作步骤、无验收条件的待办。参数只保留一处权威来源，其余给链接。区分实测、假设和随机范围；注明单位、版本和环境。失败证据、边界条件及复现所需的种子和配置不可删。
