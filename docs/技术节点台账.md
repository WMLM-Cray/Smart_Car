### 1.7 服务器 · 并行

**没有 `server_setup/` 目录，仓库里也没有 `run_parallel` / `clean_env.sh` / `WORKER_BASE` 脚本 —— 这一块未找到。** 并行的实际承载方式散在下面这些地方：

| 位置 | 内容 |
|---|---|
| `simulation/gazebo/run_road_policy_once.sh`、`run_s3_policy_once.sh` 的 `WORKER` | 一个整数决定**四样隔离**：`ROS_DOMAIN_ID=43+WORKER`、`GAZEBO_PORT=11345+WORKER`、world 文件名含 worker 号、`/tmp` 控制器 yaml 按域分文件。少一样就互相污染 |
| `run_sim.sh` | 域取 `ROS_DOMAIN_ID`（默认 60）；`GAZEBO_MASTER_URI` 端口 = 11300 + 域 |
| 训练/评估的 `--workers` | 进程池并行（`ProcessPoolExecutor`），采样进程内 BLAS 单线程 |
| `README.md` / `training/说明.md` | **共享服务器所有任务合计不得超过约定的 17 核**；训练命令本身不设 CPU 配额 |
| `docs/spica方案.md` §4.2 | 多机并行时的 ROS 域分配约定：一组用 `WORKER_BASE` 0（域 43–50），另一组用 20（域 63–70）。**代码里没有这个变量** |
| 已占用的域 | 共享服务器上 43–50、84 被别人占用；实车域 42 |

### 节点 1：WSL2 + ROS 2 Humble 仿真环境与工程骨架
- **时间**：2026-09-13（`9e985c1` → `d9e0af2`）
- **目标**：从零建一套能在 Windows 上开发、Ubuntu 里跑 Gazebo 的环境。
- **改动产出**：WSL2 + Ubuntu 22.04 + ROS 2 Humble 一键安装脚本（国内源、keyring、幂等，密钥获取三级 fallback）；四包骨架；赛道生成器原型；罚时账本；12 项测试。
- **关键结论**：Humble **没有 `ackermann-steering-controllers`**，换 `tricycle-steering`（运动学相同）；`jsDelivr` 的文本 asc 不能直接当 keyring；WSL 环境说明书成文。
- **状态**：已定案。

### 节点 2：Gazebo 仿真车模与验收脚本
- **时间**：2026-09-13 ~ 2026-09-15（`b083614` → `4ddaa47`）
- **目标**：车能在 Gazebo 里被控制器驱动，且传感器与 TF 齐备。
- **改动产出**：阿克曼四轮车模（厂家 TF 保留、物理 sensor frame）+ 雷达/相机/IMU；`sim_bringup.launch.py` 一键启动；`sim_wiring` 接线箱（补 `/cmd_vel` → 控制器、`~/tf_odometry` → `/tf` 两根线）；验收脚本 42 项 ALL_GREEN（PASS=42/FAIL=0）。
- **关键结论**：`gzserver` 不解析 `--ros-args`，无法用 remap 接线；`steering_controllers_library` 的 `enable_odom_tf` 只往专属话题发 TFMessage；车模 spawn 位姿参数化（`world`/`spawn_x/y/yaw`）后"车辆入 trackA"四项运行时验证 ALL PASS。
- **状态**：已定案（后续被节点 15 的验收工具链取代部分用途，车模本身仍在用）。

### 节点 3：赛道 A 几何解析与冻结
- **时间**：2026-09-15 ~ 2026-09-17（`e502106` → `fbc46c0`）
- **目标**：把官方图（PDF 第 11 页上半，图 9A）变成可用的锥桶坐标与场景。
- **改动产出**：`maps/trackA_cones.csv`（71 桶逐点）+ `trackA_layout.yaml`（黄 V 多边形、尺寸链、`source` 标注）；锥桶尺寸改官方 630×280×280 mm；冻结 CSV → SDF 场景（63 锥 models + world + 独立检查器 + 冒烟）；赛道改为方正布局（端部直角弯）。
- **关键结论**：图 9 的尺寸归属返工多轮（弧长定案被撤销，改尺寸链驱动重建）；黄 V 处不放锥桶、按图示肩点与角度连接；局部法向宽度约 1.386 m，与规则统一道宽 1.5 m 的关系**未确认**。
- **状态**：已定案（`trackA.world` 是历史冻结赛道，**不是**当前 `maps/` A–D 的同一评测集）。

### 节点 4：实车接入、传感器对齐与安全层
- **时间**：2026-09-16 ~ 2026-09-17（`197b3ec` → `fd797e9`）
- **目标**：零运动指令下把实车盘点清楚，再把安全层补齐。
- **改动产出**：SSH 直连 + 只读盘点/备份/采集三脚本；传感器对齐（雷达 10→12 Hz、2000→1667 点，IMU 200→100 Hz）；底盘看门狗（发指令的一停就把电调拉回中位）；基础防撞（雷达前向走廊）；车载 WiFi 脚本；systemd 相机与路由修正服务。
- **关键结论**：**轴距实测 0.33 m**（出厂源码 0.305 是别的车，队友记的 0.36 也不对）；摇杆卡住不再一直发油门；低速占空比与倒车编码器闭环硬限速 400 mm/s。
- **状态**：已定案。

### 节点 5：v1 低速转向策略（`low_speed_steering_v1`）
- **时间**：2026-09-22（`f74dc77`、`6053caa`、`ae1e635`）
- **目标**：从零训一个只输出转向的低速策略并上车。
- **改动产出**：`common/low_speed_policy.py`（52 维 × 5 帧，`DEFAULT_SPEED_SCALE=1.5`）、`common/obs.py`（48 扇区，仿真与实车共用）、训练/评估脚本、`vehicle/steer_policy_node.py`；权重与训练证据入库（`models/steering_v1/candidate_060.npz` 为实车基线）。
- **关键结论**：观测必须单一来源（实车只装 numpy，照抄迟早分叉）；域随机化增强 + Phase A 可从 npz 初始化；评估种子可配。
- **状态**：已定案（**训练线已从本仓库移除**，见节点 12）。

### 节点 6：实车标定（转向曲线 / 速度曲线 / PID）
