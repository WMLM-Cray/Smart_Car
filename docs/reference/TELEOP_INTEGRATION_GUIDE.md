racecar_teleop 是一个 ROS2 手柄映射包,负责把 /joy 转换成物理单位的 /teleop/cmd_vel。它不负责自动驾驶仲裁,也不负责把速度和角速度转换成厂家 PWM。

Windows 主副本位于 `E:\study\racecar_teleop\`,WSL 验证副本位于 `~/teleop_ws/`。主线接入前,先把包放入目标 colcon 工作区的 src/ 下。不要只做增量构建:这个包是 ament_python 包,删除或替换 Python 文件后,旧文件可能继续残留在 install/ 中。接入、改配置或删文件后执行:

```bash
cd ~/teleop_ws
rm -rf build install log
colcon build --symlink-install
source install/setup.bash
```

构建完成后先运行包内测试,再运行端到端测试:

```bash
colcon test --packages-select racecar_teleop
colcon test-result --verbose
~/teleop_ws/tools/teleop_e2e_run.sh
```

预期结果是单元测试 46/46 通过,端到端测试 9/9 通过。测试日志必须完整保存。

## 接口契约

- 输入:`/joy`,类型 `sensor_msgs/msg/Joy`
- 输出:`/teleop/cmd_vel`,类型 `geometry_msgs/msg/Twist`
- `linear.x`:前进速度,单位 m/s
- `angular.z`:偏航角速度,单位 rad/s
- 阿克曼关系:ω = v · tan(δ) / L

默认控制逻辑是:左摇杆 Y 控制速度,左摇杆 X 或配置指定的转向轴控制方向;使能按钮必须持续按住车辆才运动;低速按钮将速度缩放到低速档。实际轴编号和按钮编号以 generic.yaml 为准,接入前必须打印或核对一次配置,不能仅依据手柄外壳上的标注猜测。

## 包内置安全行为

- 松开使能按钮后输出归零;
- /joy 超过 0.3 s 未更新后自动归零;
- 小于死区的摇杆输入归零;
- 必须先松开使能,再重新按住,才会重新武装;
- 对 NaN、越界值和异常长度消息进行保护;
- 倒车时保留速度符号,角速度按同一物理语义输出。

## 主线接入两方案

**方案 A(直接 remap,仅限临时单源调试)**:把控制器的 reference_unstamped remap 到 /teleop/cmd_vel。它适合单独调试,接线少,但会绕过当前 /cmd_vel → cmd_vel_relay → controller 的统一入口,也没有手动/自动仲裁。自动导航节点和手柄同时运行时,可能产生竞争。

**方案 B(仲裁节点,推荐采用)**:teleop 保持发布 /teleop/cmd_vel,自动驾驶继续发布 /cmd_vel,仲裁节点根据当前模式、优先级和超时规则选择一个输出,再发布统一的 /cmd_vel,最后沿用现有 cmd_vel_relay 转发到控制器。这样手动接管、自动恢复和 watchdog 都有明确归属。仲裁节点应保证任意时刻只有一个有效控制源进入车辆控制器。

## 实体手柄与 WSL2

实体手柄在 WSL2 中通常不会自动出现在 /dev/input/js*。仿真阶段可以使用脚本或测试节点模拟 /joy。需要接实体手柄时,可在 Windows 侧通过 usbipd-win 将 USB 设备附加到 WSL,再确认 WSL 内存在对应输入设备;若设备直通不稳定,应先继续使用模拟 /joy,不要把"没有实体手柄"误判为 teleop 映射失败。

## 实车 PWM 转换层

实车不能直接使用仿真的 /teleop/cmd_vel 作为厂家 PWM 指令。必须增加转换节点,把物理 m/s、rad/s 转为厂家要求的 PWM 刻度,并根据 contract.json 和实车标定结果处理中值、方向、限幅、死区及超时停车。1500 + 100 × linear.x 等公式只能作为厂家代码中的初始映射参考,不能当作已标定的物理模型。

## 常见问题

- **车不动**:先检查是否按住使能;松开后必须重新按住才能复走。
- **摇杆动了但输出为零**:检查轴编号、死区设置、/joy 消息是否持续发布。
- **输出方向反了**:检查 Y 轴符号和转向轴符号,不要直接修改下游控制器方向。
- **速度手感与旧测试不同**:检查三处 wheelbase 是否统一;0.36 和 0.305 会造成不同的角速度响应。
- **改完代码但行为没变**:删除 build/ install/ log/ 后重新构建,排除旧 Python 文件残留。
- **自动驾驶和手柄互相抢控制**:不要使用无仲裁的直接 remap,检查仲裁节点是否只输出一个有效源。
- **实车方向或速度异常**:检查 PWM 转换层;仿真 Twist 不能直接当厂家 PWM 刻度解释。
- **WSL 找不到手柄**:检查 usbipd 设备附加状态,或先使用模拟 /joy 完成软件验收。
