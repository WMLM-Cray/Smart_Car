# 实车运行

部署时保留仓库结构，放在 `/home/orange-pi/autocar`。从该目录执行模块入口；不要继续把文件平铺复制到 web_teleop。

```sh
source vehicle/ros_env.sh
python3 -m vehicle.server
python3 -m vehicle.watchdog
python3 -m vehicle.steer_policy_node models/steering_v1/candidate_060.npz --speed-loop --speed 0.7
```

以上三个进程分别运行。systemd 模板提供网页、看门狗、底盘与旧版策略；系统服务安装仍需在车上验证。标定使用 `python3 -m calibration.loop_test` 等模块入口。

PWM 中位 1540，硬上限 1620，舵机中位 81，轴距 0.33 m。本次没有改变实车服务，也没有进行 ROS 或硬件验收。

## 开电调:先等底盘起来

电调上电那一刻收到什么油门就锁成中位(2026-09-30 实证,见 docs/实测/2026-09-30-curve)。所有代码把 1540 当停车,
锁错了"停车"就是在给油或倒车。`racecar-neutral.service`(vehicle/esc_neutral_boot.py)在底盘驱动起来后喂 5 s 的 1540,
之后驱动保持它;底盘重启时跟着重跑。**车开机后等网页能打开(底盘已起来)再打开电调开关**;驱动起来之前
电调收到的是下位机默认值,这段时间别开。发现 1540 下车在动或反转:关电调,`python3 neutral60.py` 或
`python3 -m calibration.esc_rearm` 发着中位重新上电。

## road_v2 实车节点(未在车上验证)

`vehicle/road_car_node.py`:转向 + 目标速度双输出,观测和推理与训练、仿真节点同一份代码(common/road_runtime.py);
安全外壳同 steer_policy_node:心跳放行、松手发中位、传感器过期回中位、防撞截停与卡死报警、SpeedLoop 闭环(上限 1620)。
和 steer_policy_node 二选一,不要同时开;开机服务仍是旧版,没改。

```sh
source vehicle/ros_env.sh
python3 -m vehicle.road_car_node models/road_v2/candidate_167.npz --speed-cap 0.5
```

`--speed-cap` 必填,范围 0.45~1.0(训练范围)。上车顺序:
1. 架空(轮子离地):看油门从 1540 慢爬、舵机随场景变化、松手立刻回中位;编码器读数虚高,不看速度。
2. 落地低速:`--speed-cap 0.5`,走廊或赛道一段,人跟车、手在停止按钮上。
3. 再逐档加上限,和 steer_policy_node 对比。

未验证的地方:目标速度每拍变化时 SpeedLoop 的跟随(仿真里是理想近似);编码器单帧 ±0.2 跳变直接进观测(训练噪声只有 0.02)。
