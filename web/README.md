# 小车监视与操作台（web）

手机竖屏优先、电脑可用的只读监视台：总览 / 地图 / 视频 / 任务 / 设置 五栏。
第一轮交付 = **连接设置 + 真实地图显示 + 视频入口 + 独立状态提示**；导航/停止**未接入**，按钮禁用并有说明。

> 红线：本页面只读。不向任何控制话题发指令、不做 SSH、不实现导航/停止。演示数据只在显式「演示模式」出现，全页常亮标识，不连控制接口。

## 快速启动

**0) 前提**：车机已连手机热点(`vivo_y78` 自动连接)，电脑接入同一热点；车机侧已有地图/相机渲染器在跑。

**1) 车机侧启动渲染器（队友现场执行，只读渲染，不动控制链）**

```bash
# 地图(map+scan+轨迹+可选路径) —— 车机 ~/racecar_team/
./display_monitor.sh start            # 可选带规划路径话题: start /plan
# 相机帧(只读渲染 /image_raw -> camera.png)
./camera_monitor.sh start             # 可选带图像话题: start /camera/image_raw
```

**2) 本机拉图（可选，二选一）**

```bash
# 方式A：永续拉两张图(地图譥相机)到 web/media/
./pull.sh <车机IP>          # IP 是热点 DHCP 动态分配，每次先查，禁止写死
# 方式B：沿用 tools/realcar/fetch_monitor.sh(只拉地图)，把输出放 web/media/
```

**3) 启动前端服务（只读）**

```bash
python serve.py                 # 默认 0.0.0.0:8123，只读
# 仅本机: python serve.py --host 127.0.0.1
# 注: Windows 若 `python3` 是应用商店别名(运行报 exit 49 / 无输出), 改用 `python`;
#     WSL/Linux 侧 `python3 serve.py` 亦可。两者行为一致。
```

**4) 打开**

- 本机浏览器：`http://127.0.0.1:8123/`
- 手机：与电脑同一热点，打开 `http://<电脑局域网IP>:8123/`（查 IP：`ipconfig` 的无线局域网适配器 IPv4）

> ⚠️ 手机能否直接访问热点下其它设备、浏览器是否有限制、后端监听地址，**需实际部署时验证，不能默认一定可达**。若不达，先在本机浏览器确认页面正常，再排查热点是否隔离了客户端互访。

## 演示模式

没连车/没拉图也能看整套界面：打开页面 → 「设置」→「进入演示模式」（有确认弹窗）。
演示模式全页顶部常亮黄色横幅，地图/相机为画布生成的占位图，不连接任何后端。

## 安全与范围

- `serve.py` 只读：只有 GET，无任何 POST/控制端点；`/media/*` 固定映射两个 PNG 文件名，静态资源走扩展名白名单 + 路径防穿越。
- 本页不「合成系统正常」：雷达新鲜度只能靠地图画面左上角 `scan/tf` 戳目视判定，故总览里雷达固定显示「未知」；定位、任务、导航、停止均标「未接入」。
- 页面断线/切后台/锁屏/刷新：不自动重发任何控制命令（本页本就无控制命令）；切后台会自动停止视频连续拉图。
- **软件停止未接入**，页面不提供红色急停按钮；现场始终依靠物理停止装置与车端安全链。
