# spica v3 模型

spica v3 是闭环规则赛道上的双输出(转向 + 目标速度)策略,53 维 × 5 帧观测。
**只用于仿真**:`vehicle/road_policy_node.py`(该节点本身要求设仿真域,拒绝实车域 42)。
实车部署节点尚未实现。

## schema 决定怎么加载

速度契约与输入宽度都由 `.npz` 自带的 `schema` 字段描述,读文件即权威,**别按目录名猜**:

    candidate_036.npz   schema = spica_v3_s3_v0.45-3_nola   -> scale 3.0, V∈[0.45,3.0], 输入 255 列
    candidate_041.npz   schema = spica_v3_s3_v0.45-3        -> scale 3.0, V∈[0.45,3.0], 输入 265 列
    cand003_s3.npz      schema = spica_v3_s3_v0.45-3        -> scale 3.0, V∈[0.45,3.0], 输入 265 列

`common/road_policy.py` 的 `spec_of()` 从后缀反解 `(scale, v_lo, v_hi)`;`_nola` 后缀
表示**网络输入层物理上不含 last_action 两列**(265→255,真删不是置零),由
`RoadPolicy.forward` 按 `w[0]` 的宽度自动走对应通路,调用点不用改。
`vehicle/road_policy_node.py --speed-cap` 的默认值也取自模型的 `v_hi`。

## 已知边界

- **这批模型都没有实车验证**,也没有经过 Gazebo 速度阶梯验收。
- `candidate_036.npz` 在 Gazebo 元素套件的 `s_bend_02` 上成绩很差:三次重复
  只有一次跑完,且那次是**擦边通过** —— 单圈 95.7 s(同赛道正常约 46 s),静止占 32.8%。
  **不要把它当"干净通过"引用。**
- `candidate_041.npz` 在官方 A–D 上综合 0.658(B 1.00 / C 0.67 / D 0.97),**A 为 0**。
  A–D 只用于验证,未参与任何训练或模型选择。
- 报告任何干净率必须同时给出 cap、评估仪器(Gazebo 还是 fastsim)、种子段与 n。
  Gazebo 与 fastsim 的数字不可比。
