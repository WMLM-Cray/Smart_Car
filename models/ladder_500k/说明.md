# 单速阶梯投资组合(5 档)

每个 `.npz` 是**单速专化**的:它在自己那一档速度上训练,也只在该档(±1 档)有效。
档位之间没有连续过渡 —— 选错一档干净率从 0.9 掉到 0.0,所以只能做最近档选择,
不能插值。选择逻辑见 `common/policy_portfolio.py`。

| 档位 | 速度 m/s | 模型 | 干净率 (n=150) | 训练步数 |
|---|---|---|---|---|
| rung1_sp1.2 | 1.2 | candidate_010 | 0.873 | 500k |
| rung2_sp1.6 | 1.6 | candidate_010 | 0.913 | 500k |
| rung3_sp2.0 | 2.0 | candidate_010 | 0.887 | 500k |
| rung4_sp2.5 | 2.5 | candidate_010 | 0.880 | 500k |
| rung5_sp3.0 | 3.0 | candidate_010 | 0.827 | 500k |

干净率是 fastsim 实测(无 guard),种子基 71000000,同种子配对 McNemar 对比 100k
版本的 p 值见 `common/policy_portfolio.py` 里 LADDER 上方的注释。**1.2 那一档
p=0.080 不显著**,点估计更好、配对 22:11 也同向,但没有到 0.05 —— 不要声称
1.2 的提升已被证明。

## 文件名后缀不是速度

`rung1_sp1.2` 里的 `1.2` 是**训练时的 SPEED_SCALE 原值**,不是部署速度。读模型
自带的 `schema` 字段才是权威:

    rung1_sp1.2/candidate_010.npz   schema = low_speed_steering_v1        -> scale 1.5
    rung2_sp1.6/candidate_010.npz   schema = low_speed_steering_v1_s2.4   -> scale 2.4
    rung3_sp2.0/candidate_010.npz   schema = low_speed_steering_v1_s3     -> scale 3.0
    rung4_sp2.5/candidate_010.npz   schema = low_speed_steering_v1_s3.75  -> scale 3.75
    rung5_sp3.0/candidate_010.npz   schema = low_speed_steering_v1_s4.5   -> scale 4.5

`SteeringPolicy` 自己从 schema 反解 scale(见 `common/low_speed_policy.py`),
部署时不必再设环境变量。**别按目录名猜 scale。**

## 与 steering_v1 的关系

`models/steering_v1/candidate_002.npz`(m4)覆盖 0.6~1.0 m/s(实车开机服务 `vehicle/systemd/racecar-policy.service` 目前仍加载 candidate_060,换 m4 要改那里);
1.2 以上由本目录的阶梯接手。两者观测维度相同(52 维 × 5 帧),同一个
`SteeringPolicy` 类可以加载,靠 schema 区分 scale。
