# Gazebo 最小验证工程

保留两个 ROS 包：racecar_sim（车模、控制器、传感器、接线与启动）和 racecar_test_assets（红蓝锥桶模型与环境钩子）。
从历史提交 0ed23c4 恢复，未恢复导航、旧策略训练器、历史截图或批量实验。

## 构建与启动

在安装 ROS 2 Humble 与 Gazebo Classic 的 Ubuntu 环境，从仓库根目录执行：

```sh
source /opt/ros/humble/setup.bash
cd simulation/gazebo
rosdep install --from-paths src --ignore-src -r -y
colcon build --symlink-install
bash run_sim.sh use_gui:=false
```

run_sim.sh 固定仿真域 43，只启动仿真，不自动使能策略，也不清理其他进程。
默认 racecar.world 是空场。历史 trackA.world 是旧版冻结赛道，不能当作当前根目录 maps/A–D 的同一评测集。

## 接口与验证边界

/cmd_vel 使用 m/s 与偏航角速度 rad/s；绝不能发送实车 PWM。
已恢复 /scan、IMU、里程计与 TF 接线所需工程。轴距 0.33 m，雷达 1667 点、12 Hz。
Gazebo max_steer_angle=0.55 是左右车轮关节限位，不能直接等同 FastSim 的等效自行车角 0.379；仍需验证控制器到实际转弯半径。
Gazebo 速度控制没有复现 ESC 起转平台与真实 SpeedLoop，当前只恢复工程，不宣称完成 sim-to-real 对齐。

本轮在 Windows 做语法、XML/YAML、依赖路径与资源引用检查；ROS 构建和 Gazebo 动态运行待 Ubuntu 环境验收。
