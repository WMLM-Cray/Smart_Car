# 车辆参数与接口契约检查 v1

这是独立、只读的离线检查工具，不是新控制层，不连接车辆、不启动ROS、不执行目标仓库中的Python代码、不改Git配置或主项目文件。契约为审查草案，真实硬件事实的依据来自用户回报或仓库记录，并非本工具重新测量。

## 使用

Python 3.10及以上，依赖PyYAML（requirements.txt）。在本目录运行：

```powershell
python -m unittest -v test_contract.py
python check_contract.py --repo 'F:\影音\BaiduSyncdisk\programss\华为小车\07-仿真系统' --output '..\contract-report-new.json'
```

Linux同样支持，传对应仓库绝对路径。输出必须是目标仓库外的新文件，禁止覆盖。返回码：0=已检查的数值约束未发现失败；1=契约违反；2=输入缺失、解析或配置错误。**0不表示可以给电机上电，也不代表所有差异消失。** REVIEW、KNOWN_DIFFERENCE、UNVERIFIED必须保留在报告中。

## 契约内容

- facts：实车数据及来源可信度；0.36m轴距为用户报告的实测，非工具自行测量。
- parameters：跨二维、Gazebo及手柄的目标参数。共同写错同一个数仍会失败，不仅比较彼此相等。
- known_differences：角度端点、量程字段、TF名称、PWM模型、相机。
- interfaces：物理速度与原始控制通道的含义，特别区分`/teleop/cmd_vel`和`/teleop_cmd_vel`。
- unverified：实体验证、下位机保护、运行时参数覆盖等不可由静态扫描证明的事项。

项目Python使用AST提取字面量，YAML使用safe_load。复杂表达式或结构变化显式报错，不猜值、不回退为零。安全层只提取源码默认值；launch/命令行覆盖、实际设备映射及唯一发布者必须另做运行时验证。接口表是人工审查说明，不是自动验证的ROS图。

## 本次产物和独立性

当前工具仅针对现有源码结构实现数值契约、手动控制上限和超时顺序检查；它不自动修改参数，也不生成部署配置。PWM1550与1540作为已知不同配置报告，**不自动把二维动力学模型改成真实驱动映射**。

报告绑定读取文件的SHA256、契约SHA256、HEAD及UTC时间。工作树可能存在未提交修改，因此HEAD不等于证据版本，实际文件hash更重要。运行期间文件若被GLM修改，报告不是原子快照，应在稳定检查点重跑。

后续交给GLM选择性接入时，建议保留本工具为独立检查目录，先不让它成为生产配置生成器。不要删除历史证据，不需要为本工具改动真实车辆。

## 不覆盖的能力

运行时实车参数、驱动PWM映射正确性、下位机失联停车、真实串口输出、相机标定、碰撞/导航间隙、RL成绩均不在本工具验证范围。独立运动轨迹对账是后续模块，本次尚未实现；不要将数值契约通过宣传为跨仿真/实车运动一致。
