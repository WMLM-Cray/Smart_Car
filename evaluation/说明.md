# Gazebo 受监督跑批（本 PR 的仪器入口，2026-10-08 补）

- **入口**：`evaluation/corridor_arm_run.sh <ARM> <cap> <赛道> <reps>`
  （`<reps>` 是局数或区间 `2:3`；赛道给绝对路径即用仓内认证副本 `evaluation/panel/track_A..D`，
  给名字则去 `$TEAM_REPO/runs/gen_suite_20260926/<名字>`）。
  底层是 `evaluation/run_gazebo_supervised_smoke.sh`：**必须显式给 `TEAM_REPO` 与 `PYTHON`**
  （仓里不带机器路径默认值；只需要一个解释器 —— 脚本按它推出 `VENV_PYTHON` 与 `VENV_ROOT`，
  真要用别的 venv 再显式给 `VENV_ROOT` / `VENV_PYTHON` 覆盖），
  并先 `source /opt/ros/humble/setup.bash && cd simulation/gazebo && colcon build`（约 20 s）。
  **build 必须带 ROS 环境**：不 source 就跑 `colcon build` 会在 `racecar_test_assets` 上报
  `Could not find a package configuration file provided by "ament_cmake"`；而且失败仍会留下一个 stub
  `install/setup.bash`，于是整局会**静默换成队友那份旧几何 `racecar_sim`**（几何 0.33/0.07/0.21，
  读数不可比）。现在入口与 runner 都会核对 `racecar_sim` 的实际来源：不是本仓 `install/` 就拒绝，
  要故意跑旧几何必须显式 `SIM_SETUP=<队友>/install/setup.bash`（此时 `launch_manifest.json` 记
  `sim_in_repo: false`）。
  直接调底层脚本时，若 `--policy-entry` 指到 `arms/corridor_arm.py`，还要给 `CORRIDOR_ARM`（臂身份，
  该文件第 60 行不设就是 D 臂）；缺了 runner 会拒绝，因为那不是 `arms/VERSIONS.md` 里的口径 ——
  从 `corridor_arm_run.sh` 起跑则由它自动 `export`。
- **判读**：`evaluation/ad_lap_verdict.py <cap> --arms Y,A --runs panel`
  （`--runs` 区分两批跑批目录：`panel` = 仓内宿主 + 仓内实测 sim 的新尺子，`gz_official` = 旧队友 sim，
  两批 cap/臂名相同，混读会把分母算错）；逐行清单用 `evaluation/ad_cap_status.sh <cap>`。
- **冻结闸门**：只接受 `guard=0.25 / seconds=140 / warmup=5`，别的组合直接 `CONFIG ERROR` 拒跑；
  已存在的输出目录一律 `REFUSE`（不覆盖）。
- **口径与证据**：干净率与圈速三口径、逐局读数、混杂因素见 `docs/REPORT_armY_cap22_four_track_20261008.md`
  与 `docs/整改参考数据与路线方案.md`；每局 `report.json` + `policy.csv.ver` 自带指纹；
  臂版本规矩见 `arms/VERSIONS.md`。
- 本 PR **不收**实验过程件（历史臂存档、各版预登记、各阶段实验报告与笔记、`runs/` 大产物），
  它们在归档分支 `exp/archive-20261008`（= `09fc7d4`）。

# BEV 录制 → 回放工具链(2026-10-24 整理)

所有 BEV 图 / 视频统一用 PIL 点阵画法(`common/bev_view` + `evaluation/bev_video`),模型视角只画模型真能看到的层。

- **车上录制**:
  - `vehicle/bev_logbook.py`(road_car_node 自带):每段 `seg_NN/frames.npz`,~3 Hz 的模型 BEV 输入 + 位姿 / 转向 / 目标车速 / 车速 / 事件,和 `seg.npz` 建图。
  - `calibration/drive_record.py`:全速率原始雷达(1667 点)+ 编码器 + IMU + 摄像头 → `sensors.npz`。
  - `calibration/accel_record.py`(`racecar-accel-record` 开机自启):编码器 / IMU / 下发指令,无雷达。
- **实车回看**:`python -m evaluation.logbook_replay LOGBOOK/seg_* --map maps/realA_1023.yaml`
  左 = 实车锥桶图 + 轨迹(推算位姿 → 锥桶配准纠偏 → 整段对地图 ICP),右 = 车上模型当时的输入。
- **仿真对照**:`python -m evaluation.sim_lap_video --model M.npz --track realA_1023 --cap 2.8`
  车上条件(纯雷达、无 YOLO、默认不截停)跑整圈,左真值右模型视角;和实车回看同一画法。
- **还缺**:从 `drive_record` 原始扫描离线重算 `BevRuntime` 模型输入(改了 BEV 代码后能在实车数据上重算对比);车上 `bag_export.py`(`bag_map` / `real_map_check` 读它的输出)不在仓库。
- 车身自遮挡:`CarParams.self_box`(车尾两根天线),`common/bev.lidar_points` 统一去掉;10-24 前录的 `frames.npz` 里还带着天线点和它在雷达记忆里的拖影。
